# Application Support Analyst / Developer - Fundamentals

## 1. Application Support

Application Support involves maintaining, monitoring and troubleshooting software applications to ensure they work correctly.

**Main Responsibilities:**
- Resolve application errors.
- Monitor application performance.
- Troubleshoot technical issues.
- Maintain and upgrade applications.
- Support users.
- Improve existing systems.

## 2. ITIL and Incident Management

| Concept | Meaning |
|---|---|
| Incident Management | Restoring normal service after an interruption |
| Problem Management | Identifying and managing underlying causes of incidents |
| Change Management | Managing changes to IT systems |
| SLA | Service Level Agreement – agreed service targets |
| RCA | Root Cause Analysis – finding the underlying cause |
| Escalation | Passing an issue to a more appropriate support team |

## 3. Troubleshooting Techniques

**Steps:**

1. Identify the problem.
2. Reproduce the issue.
3. Check logs and error messages.
4. Identify possible causes.
5. Test a solution.
6. Verify the fix.
7. Document the resolution.

**Common techniques:**
- Log analysis
- Root Cause Analysis (RCA)
- Debugging
- Error monitoring
- Performance analysis

## 4. Database Fundamentals

**Important concepts:**
- SQL queries and JOINs
- Stored procedures
- Indexes
- Transactions
- Database connections
- Query optimisation
- Database permissions

**Tools:** SQL Server, PostgreSQL, MySQL.

## 5. API Fundamentals

An API (Application Programming Interface) allows software applications to communicate.

**HTTP Methods:**
- GET – Retrieve data
- POST – Create data
- PUT – Replace data
- PATCH – Update part of a resource
- DELETE – Remove data

**HTTP Status Codes:**
- 200 – Success
- 400 – Bad Request
- 401 – Authentication required
- 403 – Access forbidden
- 404 – Resource not found
- 500 – Internal server error
- 503 – Service unavailable

**Tool:** Postman.

## 6. Software Development

## 7. Application Monitoring

Monitoring helps identify application errors and performance problems.

**Important metrics:**
- Application availability
- Response time
- Error rate
- CPU and memory usage
- Database performance
- Failed transactions

**Tools:** Azure Monitor, Application Insights, Grafana.

## 9. CI/CD and Deployment

**CI (Continuous Integration):** Automatically building and testing code changes.

**CD (Continuous Delivery/Deployment):** Preparing or automatically releasing software changes.

**Important concepts:**
- Git branching
- Pull requests
- Automated testing
- Build pipelines
- Deployment
- Rollback
- Version management

**Tools:** GitHub Actions, Azure DevOps, GitLab CI/CD.

## 11. Key Concepts to Remember

- **Incident:** An unexpected interruption or reduction in service quality.
- **Problem:** An underlying cause or potential cause of incidents.
- **SLA:** Agreed service performance targets.
- **RCA:** Investigation to identify underlying causes.
- **API:** Interface enabling communication between software systems.
- **Debugging:** Finding and correcting software defects.
- **Logging:** Recording application events and errors.
- **Monitoring:** Tracking application health and performance.
- **UAT:** Testing whether a solution meets business needs.
- **CI/CD:** Automating software integration, testing and delivery.


**Summary:**

Application Support combines **troubleshooting, database management, software development, monitoring, incident management and business analysis** to keep applications reliable and improve their functionality.
